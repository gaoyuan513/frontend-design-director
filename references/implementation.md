# 前端实现指南

## 接入现有项目

- 从用户会走到的路由或组件入口开始，找出使用的布局、设计令牌、基础组件、数据和样式边界。局部修复沿用这些入口，先用真实内容复现，再调整出问题的层级。
- 复用现有组件的语义、键盘行为和状态接口。多处需要同一种新增变体时，优先补到现有组件中。只服务当前页面的排版或动效留在页面内。
- 新页面先完成一条可操作路径，再按实际需求补齐次要区域。项目已有组件库或动效工具时沿用。需要新依赖的功能应能对应到清楚的用户体验，例如中断后可恢复的多段转场，或用于探索作品的空间导航。

## 按设计稿、截图或参考实现

自有或获授权的设计稿可以作为精确还原目标。第三方案例适合提取构图、层级或交互原则，以项目自己的素材和视觉语言实现所需功能。

1. 确认参考所对应的页面、视口和状态。能检查设计源文件时，优先读取布局约束、组件变体、字体、令牌和可用素材。仅有截图时，从对齐关系、留白、尺寸比例和文字层级提取规则，把估算值集中在相关样式中。
2. 把设计拆成布局、可复用组件和素材。映射到项目主题及组件变体，按参考保留主次关系、配色、间距和裁切。对结果有明显影响的字体、图标和图片替代方案应在交付时注明。
3. 用实际内容决定何时换列、换行或切换导航。桌面参考缺少移动布局时，沿阅读顺序重排，保留主操作和关键内容，再补齐任务涉及的悬停、聚焦、选中、忙碌和错误状态。标明由参考推导的视口与状态。
4. 在相同视口、数据和交互状态下比对实现与参考。有具体偏差时优先检查容器宽度、对齐、文字换行和素材比例，再验证相邻宽度的过渡。按[浏览器验收](quality-checklist.md)验证可操作性。

## 响应式和媒体实现

- 页面用正常文档流承载主内容，用 Grid 或 Flex 表达对齐与重排。根据内容挤压点选择断点。组件在不同容器中复用时，判断是否需要容器查询。用长标题、宽表格及实际语言内容试排。
- 详情、列表或正文的 DOM 顺序保持可读。窄屏优先让主要任务顺畅完成，按需要收进次要区域。表格确需保留横向列关系时，把横向滚动限制在表格容器内。
- 为图片和嵌入媒体预留尺寸；根据不同屏幕选择裁切与资源大小。首屏关键媒体及时加载，较重的装饰效果可在核心内容就绪后加载。确保媒体加载失败时仍能阅读内容或操作页面。涉及拖拽、滚动编排或空间导航时参照[交互模式](interaction-patterns.md)。
